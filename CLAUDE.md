# Third Line (repository: hockey-roguelite)

The game is called **Third Line** (`src/data/game.json`, `index.html`, the manifest). The repository, the web address and the storage keys on the device keep the old name. It is a mobile arcade 3-on-3 hockey roguelite, built once as a TypeScript web game. It is played on a phone with a Bluetooth Xbox controller and installs to the home screen. No App Store release.

- Design: `docs/GDD.md` is the source of truth.
- Decisions the design doc does not cover: `docs/DECISIONS.md`.
- Phases, prompts and exit tests: `docs/IMPLEMENTATION_PLAN.md`.
- What comes next, in the owner's order: `docs/ROADMAP.md`.
- Live games across devices: `docs/ONLINE.md`. Step 0 (the logic, on a made-up wire) is built; nothing in the game uses it.

## Stack

| Part | Tool |
| --- | --- |
| Language | TypeScript, strict |
| On-ice game | Phaser |
| Menus | Preact (HTML and CSS) |
| Build | Vite |

Exact versions are pinned in `package.json`.

## Folders

```text
src/core/    game rules: players, grades, cap, gear, packs, XP, aging, contracts, trades, prestige, cash, staff, facilities, mascot, run map
src/sim/     on-ice simulation: physics, AI, game rules; runs headless
src/game/    Phaser scenes: drawing, camera, controller input, audio
src/ui/      Preact menu screens
src/data/    JSON tuning tables
tests/       unit tests and headless balance runs
docs/        GDD.md, DECISIONS.md, IMPLEMENTATION_PLAN.md, TUNING.md
```

**Hard rule:** nothing in `src/core` or `src/sim` may import from `src/game`, `src/ui`, Phaser, Preact or the DOM. They may import from each other and from `src/data`.

It is enforced twice:
- `tests/architecture.test.ts` scans those folders for forbidden imports and DOM globals.
- `tsconfig.core.json` type-checks them with no DOM library, so DOM use fails `npm run typecheck`.

**Randomness:** all of it goes through `createRng(seed)` in `src/core/rng.ts`. `Math.random` is banned everywhere in `src` (also checked by `tests/architecture.test.ts`). Use `rng.fork('label')` to give a subsystem its own stream.

## Run, test, deploy

```bash
npm install        # once
npm run dev        # local server; prints a network address for the phone on the same Wi-Fi
npm test           # all tests, once
npm run typecheck  # whole project, then core and sim without the DOM
npm run balance    # headless AI-vs-AI series: -- --games 200 --home 90 --away 70 (add --naive for a scripted human)
npm run measure    # the measurements in docs/TUNING.md: -- defence|breakaways|styles|bosses|rinks|seasons|all [--games N --level L --difficulty rookie|pro|allstar --player script|novice|idle]
npm run seasons    # league health and the economy over many seasons: -- --seeds 20 --years 20 [--style cautious|balanced|spender]
npm run build      # production build into dist/
npm run preview    # serve the production build locally
```

Deploy: push to `main`. `.github/workflows/deploy.yml` runs the type check and tests, builds, and publishes to https://tgpiercy.github.io/hockey-roguelite/. A failed check blocks the deploy.

The site lives under `/hockey-roguelite/` (`base` in `vite.config.ts`). Controllers need HTTPS or localhost, so test on the phone from the deployed link.

## Standing rules

- Tuning numbers live in `src/data` and never in code.
- Every rule in `src/core` has a unit test.
- No image or font files: menus are HTML and CSS, the rink is drawn in code.
- Ask before adding a dependency.
- `docs/GDD.md` is the source of truth for design; `docs/DECISIONS.md` records anything we decide that it does not cover.

## How the game and the save are protected

- `src/ui/safety.ts`, called from `src/main.tsx`: `keepOffline` registers `public/sw.js` on the built game only and, after the page has loaded, sends it every file the page is made of; `protectStorage` asks the browser to keep the save; `watchForCrashes` shows a bar (`#crash`, plain elements) on an error or an unhandled rejection, once, ignoring `isBenign` ones, with the stored save offered as a file.
- `public/sw.js` is plain JavaScript, not built: the page is fetched from the network first and from the kept copy when there is none; every other file of ours is served from the copy first. A `keep` message lists the current files; anything else kept is let go. `tests/offline.test.ts` runs it against a stand-in cache and network. Changing the cache's rules means changing `CACHE`'s name.
- The built-in test browser refuses to register any service worker, so offline play cannot be checked there: it has to be tried on the phone (open once with a connection, then with none).
- The save: `noteExported` and `lastExport` record when the save was last exported (in local storage, apart from the save); `backupDue` and `backupWords` are the reminder. `BACKUP_KEY` is a second document in the same store: the franchise as the current season began, written by the set-up screen and restored from Save and load.
- **The address bar** (`src/ui/fullscreen.ts`): `screenPlan` (pure, tested) says whether to do nothing (opened from the home screen, already full screen, or not a touch device), to ask for full screen on a touch (`fullscreenOnTouch`, from `main.tsx`, gated by `Prefs.fullscreen`), or to tell the player to add the game to the home screen (an iPhone, where a page cannot go full screen). Not checkable in the test browser: it has no touch.
- The on-screen Pause button (`#tune`) is at the top left of the rink, clear of the scoreboard and of the bars along the bottom.
- A game pauses on `gamepaddisconnected` as it does when the page is hidden (`matchView.tsx`).
- **A season game in progress is kept** (`src/ui/keptGame.ts`, `src/sim/snapshot.ts`): `playMatch({ keep: key })` writes the world to the save store under the key `game` when the game is paused or hidden, on `pagehide`, every `keepGameSeconds` (`rinkLook.json`) and at the final horn, and forgets it when the player leaves the game. `packWorld` and `unpackWorld` turn a world into plain data and back (the random generator as its seed and `rng.state()`, made again by `rngFrom`); `tests/snapshot.test.ts` steps a game picked up again beside the original and compares every step. `playSeasonGame` in `App.tsx` asks `keptGame(key)` first and passes it as `resume`: the scene uses that world in place of a new one, and the game opens paused. The key names the season's seed, the game's number, the strikes and the opponent, so any other game waiting makes it stale; it is also refused unless the same build wrote it (the page's script names). The game screen's Play row reads "Carry on" (`keptWords` in `useApp`). Exhibition, practice and the first skate are not kept. Anything added to the world must stay plain data, or keeping breaks as replays do.

## How the franchise side fits together

- Rules live in `src/core`, each with tests in `tests/player.test.ts` and `tests/league.test.ts`:
  `player.ts` (overall, grade, cap hit), `names.ts`, `generate.ts` (seeded league), `league.ts` (the data shapes and lookups),
  `roster.ts` (cap, sign, release, can the team play), `lineup.ts` (two lines of 3 and a goalie; auto-fill; repair),
  `save.ts` (save document, version check, migration steps), `matchup.ts` (a dressed lineup becomes the simulation's `TeamSetup`; a result updates the record).
- Tables are in `src/data`: `grades.json` (bands and cap ranges), `overallWeights.json`, `league.json` (cap, roster sizes, how the league is generated), `names.json`.
- Roster moves return `{ ok: true }` or `{ ok: false, reason }`; the reason is written to be shown to the player as it is.
- A save is one JSON document with a `schemaVersion`. Loading always goes through `fromSave`. When the save shape changes, bump `SAVE_VERSION` and add a step to `migrations` in `save.ts`; never break old saves.
- Menus are in `src/ui`: `App.tsx` holds what every screen shares (`useApp`: the franchise, which screen is showing, `go`, `after`, `commit`, `tile`, `card` and the rest, handed on as `AppCtx`) and the screens themselves are in `src/ui/pages/`, one file per group (`start`, `home`, `gear`, `offseason`, `club`, `league`, `groups`, `roster`, `play`, `settings`; the `Screen` type and the small tables are in `shared.tsx`). Each file is a function that draws its own screens or returns nothing, and `App` asks them in turn; `settings` is last and answers when nobody else does. Where these notes say a screen is "in `App.tsx`", look in `pages/`. A new name in `useApp` that a page needs must be added to its returned object. Each screen is one `Menu` (`Menu.tsx`), so all of them work the same way with the controller. `menuInput.ts` turns d-pad, left stick, A and B (and arrows, Enter, Escape) into menu moves; the right stick scrolls whichever of the side panel and the list has more than fits (`scrollPixels` and `lookPush` in `menuScroll.ts`, `menuScroll` in `controls.json`). On a controller the browser calls "standard" the stick is axis 3; on any other it is whichever of the listed axes has moved furthest from where it rested. The controller read-out shows the other axes and which layout the browser reports: ask the owner to read it out if scrolling does nothing. `storage.ts` is the IndexedDB wrapper; the game saves after every roster move, lineup change and game.
- `matchView.tsx` starts a game on the ice between two dressed teams and tears it down when the player leaves the summary; the menus are hidden meanwhile.
- Pausing: `matchView.tsx` holds the paused flag and `RinkScene` reads it through its `paused` option (it still draws, but runs no steps). The pause menu is `src/ui/PauseMenu.tsx`, ordinary `Menu` screens rendered into `#pause`, with `menuInput` started while it is open. The Menu button, Tab, Escape, the on-screen Pause button and a hidden page all pause. "End game" calls `scene.forfeit()`, which ends the game with `forfeitResult` (`src/sim/match.ts`): `forfeit: true` and the other team as winner, so `recordGame` counts a loss. The tuning panel opens from the pause menu.

## How the season run fits together

- `src/core/quickGame.ts` settles a game from team strength without simulating it; the season uses it for "Simulate" and the health checks use it for whole seasons.
- `src/core/season.ts` is the season as a state machine. `Franchise` (league, record, season state, artifacts) is everything that is saved. Every action (`startSeason`, `travel`, `recordGame`, `train`, `chooseEvent`, `buy`, `healStrike`, `leaveShop`, `pickArtifact`, `setLoadout`, `abandonSeason`, `endSeason`) takes the franchise, changes it, and returns `{ ok, message }` or `{ ok: false, reason }` written for the player. `matchup(f)` gives the game waiting to be played, or null.
- `src/core/seasonMap.ts` generates the map from a seed; `src/core/bosses.ts` builds boss teams and ranks the AI teams by strength.
- Content is data: `src/data/season.json` (map shape, strikes, rewards, prices, AI level by region), `powerups.json`, `artifacts.json`, `events.json`, `bosses.json`. Tests in `tests/season.test.ts` check every entry is valid, so new content only needs a data entry.
- **Conditional modifiers** (`src/sim/conditions.ts`): a modifier may carry `when` (leading, trailing, tied, lastPeriod, overtime: on while true for the team) or `on` with `seconds` (goalFor, goalAgainst, bigHit, save, steal, pass: a timed boost through `startBoost`). Only plain modifiers go into a player's `baseFx` (`plainOf`); the rest sit on `TeamState.conditional`, and `stepConditions` keeps `TeamState.active` right and starts the boosts. `refreshBoosts` applies boosts plus `active`. `when: "home"` is settled in `season.teamModifiers` before the game. `artifactModifiers` gives each conditional modifier the artifact's name as its `label`, which the rink shows while it is in force. A **bargain** artifact has `bargain: { games, handicap }`: `season.bargains` counts the games down, and until then the handicap stands in for its modifiers. New conditional content is a data entry; `tests/conditions.test.ts` checks every one.
- **One modifier system** (`src/sim/modifiers.ts`). A modifier is `{ stat, op: 'add' | 'mul', value }`. Stats the simulation reads are the fields of `SkaterEffects` and `GoalieEffects`; anything else (`currencyGain`, `shopPrice`, `trainingBonus`, `powerupDropChance`) is read by the season rules. Artifacts, boss traits, event effects and powerups are all lists of these. Gear (Phase 6) and staff (Phase 8) should use the same system, not new special cases.
- Lasting team modifiers go into a game through `TeamSetup.modifiers`. A powerup is loaded through `WorldOptions.powerups`; `src/sim/powerups.ts` starts its timed boost when the button is pressed and ends it on the game clock. `GameResult.powerupsUsed` tells the season which ones to take out of the bag.
- A game step on the map offers a plain game and an **elite** one (`Stop.elite`): `matchup` makes it harder and `settleGame` pays more and offers artifacts. Artifacts are cleared by `startSeason`: each run is its own build. `train(f, playerId, choice)` takes one of `trainingChoices` (all-round, one rating, or a trait from `season.json`); rating boosts and traits are kept as modifiers in `season.training` and reach the ice through the same hook as gear. `season.scouted` (a shop's report or an event) weakens the next boss.
- **Charters and handicaps** (`src/core/charter.ts`, `src/data/charters.json`): `startSeason(f, setup)` (and `beginSeason(f, setup)`) takes a charter id and handicap ranks, kept on `season.charter` and `season.vows`. Both are lists of modifiers: `setupModifiers` joins them, and `season.stat()` and `teamModifiers` read them beside the artifacts. Season-level stats they use: `opponentRating`, `opponentLevel`, `shopPrice`, `maxStrikes` (read through `maxStrikes(f)`), `noSimulate`, `artifactChoices`, `noRepairs`, `startingPowerups`, `currencyGain`. A charter may also give every opponent modifiers (`opponent`), change a rule of every game (`rules`, passed on as `Matchup.rules`), set the number of regions (`season.regions`, read through `seasonRegions(f)`), and count your defencemen's goals (`season.defenceGoals`). Each handicap rank is a point: `vowPay` multiplies Pucks, `vowPackLuck` multiplies pack luck in `awardPack`. A new charter or handicap is a data entry.
- **The weekly run** (`src/core/weekly.ts`): `newWeekly(weekKey(y, m, d))` is a franchise of its own, generated from the week's key, with `season.weekly` set, one region, and a charter and two handicaps drawn by `weeklySetup`. It ends when its boss is beaten (`finishStop`), with no playoffs. In `App.tsx` your own franchise waits in `mainRef` while it is played, saves go to the `weekly` key (`storage.ts`), and `claimWeekly(main, result)` gives the one Gold pack a week. Core never reads the date: the UI passes it in.
- **The ringer** (`src/core/ringer.ts`): after a boss's artifact the stage becomes `ringer` (`season.ringerOffer`); `pickRinger(f, index | null)` hires one or none. `dressUser` puts `season.ringer` in the lowest-rated dressed skater's place (`withRinger`). His id is `RINGER_ID`; `isGuest(id)` is true for him and the mascot, and XP, milestones and the scoring table skip guests. Anything that walks the season by hand must handle the `ringer` stage.
- **Recipes, unseen-first**: an artifact with `recipe: [a, b]` is never offered: `gainArtifact` makes it when both halves are held. `f.seen` remembers artifacts held and events met; ones never seen are offered `unseenWeight` times as often, and come first on a new map. That number and the ringer's are in `src/data/run.json`.
- **The trade deadline** (`src/core/deadline.ts`, numbers under `deadline` in `offseason.json`): `finishStop` sets `season.deadline = {}` when the boss before the last region is beaten (not in a weekly run); `settleGame` deletes it, so it passes with your next game. `deadlineOffers(f)` draws the offers the first time it is asked (from the season's seed) and keeps them on `season.deadline.offers`; `acceptDeadline(f, index)` makes the trade. Both go through `judgeTrade` and `swapPlayers` in `trades.ts`, which are `evaluateTrade` and `trade` without the off-season's conditions. Nothing that walks a season by hand needs to know about it: it is not a stage. Screens: `pages/deadline.tsx`.
- **The season on one card** (`src/core/recap.ts`, `src/ui/RecapPicture.tsx`, sizes under `recap` in `mapLook.json`): `seasonRecap(f)` is the facts, read while the season is still on the franchise; the picture is a plain SVG whose colours are read from the page's CSS variables when it is drawn, so `savePicture` can turn it into a PNG.
- **Exhibition tournament** (`src/core/tournament.ts`): `newTournament`, `tournamentOpponent`, `afterTournamentGame`; kept in `App.tsx` state only.
- All randomness in a season comes from its seed and a roll counter, so a season replays exactly.
- `tests/seasonRun.test.ts` plays whole seasons automatically with real simulated games; it prints how each ended.

## How two players fit together

- The world holds up to two humans: `world.human` (player one) and `world.human2` (co-op on team 0, or versus on team 1; `WorldOptions.second`). `step(world, input, tuning, input2)` takes one input each. Never ask "is this the human's skater" through `world.human` directly: use `humanOf(world, playerId)`, `humansOn(world, team)`, `partnerOf` and `teamInput` in `src/sim/team.ts`.
- Playing alone, control follows the puck as it always has. With a co-op partner each keeps his own skater: `updateControl` never hands you your partner's, `givePuck` pulls nobody onto the free skater, and a pass moves only the passer (and only to the free skater). Either may call a line change or pull the goalie; powerups are player one's.
- Controllers: `assignSeats` in `src/game/gamepad.ts` says who has which (`readGamepad(player)`). A second controller joins while joining is open (on the menus: `openJoining`), and then both seats are fixed. `padMap(player)` keeps a layout each (`hockey-padmap`, `hockey-padmap-2`). `InputReader(1)` is player two: controller only, no keyboard or touch.
- `RinkScene` takes `second` and draws player two's ring in `reticle.colour2`; `playMatch({ second })`. In `App.tsx`, `joined` and `together` hold whether a second controller has joined and the mode; a season game with a second player is co-op and counts as any other game.

## How the league fits together

- `src/core/standings.ts`: the table (`Standings`, `Row`, `points`, `ranked`), a round of AI games (`playRound`, settled from strength), `creditGoals` (who scored), `playoffField` and `settleSeries`. `season.leagueRound` runs after each of your map games: your result, your opponent's, then everyone else's. The table, the scoring and the last round's results live on the season (`standings`, `scoring`, `lastRound`: all optional, so a season begun earlier still loads and finishes by the old rule).
- The playoffs are a bracket (`season.bracket`): you and the best three AI teams, seeded by the table. `homeGame(f, n)` in `economy.ts` says where a game is played: it alternates, except that `season.homeOverride` gives the higher seed games one and three of a series.
- `src/core/chronicle.ts`: `leagueNews` (worked out from the season each time, nothing stored), `seasonAwards`, `closeChronicle` (called by `finishSeason`: awards, the season's line in `f.history`, career lines in `f.career`, next season's `f.rivals`), `clubRecords` and `rememberRetired`. `isRival` in `season.ts`; beating one pays more.
- Screens: League, Standings, News, Trophy room in `App.tsx`.

## How commentary and music fit together

- `src/game/commentary.ts` (pure, tested): `Commentator.call(events, context, now)` returns the line for the most important thing in a batch of events, from the wordings in `src/data/commentary.json`. A goal's line is put together from parts under `goal` there: `how` it went in (plain, one-timer, tip: the commentator notes the last shot), then either what it means for the score (`momentOf`: first goal, ties, takes the lead, within one, hat-trick, overtime winner) or who passed (`from`, some of the time) and the score. `once` holds lines said once a game at most; `sayChance` makes the small things (pokes, freezes, fakes) go uncalled some of the time; with the margin at `quietMargin` only calls of priority `quietBelow` and up are made. A save straight after a one-timer uses `saveOneTimer`. `RinkScene` shows it under the scoreboard and hands it to `onCall`; `matchView` passes that to `src/game/voice.ts` (the browser's speech synthesis) when the preference is "voice". `Prefs.commentary` is off, text or voice. **How it is said** is `src/game/voicePlan.ts` (pure, tested) from `src/data/speech.json`: `rankVoices` orders the device's English voices by what their names say of them (natural and enhanced first), `voiceFor` picks the player's choice (`Prefs.voice`, empty for the best) and gives the announcer's kinds (opening, period, final) the next best voice, `deliveryFor(kind, tense, roll)` is the rate, pitch and loudness for each kind of call (a goal shouted, a period read level; `tenseNow` lifts it late in a close game; a little varied each line), and `spokenText` reads a score as "3 to 2". `onCall` carries the call's kind and whether the game is tense. A new kind of call needs a delivery in `speech.json` (a test says so). Settings has "Commentary voice", which steps through the device's voices and says a sample. There are no sound files: the owner chose the best of the phone's voices over recorded clips or a voice engine.
- `src/game/musicScore.ts` (pure, tested) reads tunes written as note names and beats in `src/data/music.json` and says which piece goes with what (`stingFor`, `resultPiece`). `src/game/music.ts` plays them through the game's own audio context (`gameAudio.bus()`): `music.loop('theme')` on the menus, `music.sting(...)` for moments. `music.played` counts what was asked for, like `gameAudio.played`. No continuous music during a game.

## How the club's voice, its people and the town fit together

- **The theme** (`docs/GDD.md`, "Theme"): a small-town club of players nobody else wanted, staying open one season at a time. Plain and warm; no farce. New wording should sound like a local paper or a radio announcer.
- **The paper and the announcer** (`src/core/voice.ts`, `src/data/voice.json`): `paperName(team name)` and `announcerName(team name)` are worked out from the name, nothing stored. `seasonContexts(f)` lists what is true of the season now (a streak from `season.streak`, the last strike, a rival, a veteran, the books near the fire sale, and so on); `leadContext` picks the most important; `pregameLine(f)` is the announcer's line on the game screen and at the opening faceoff (`playMatch({ opening })`); `paperLines(f)` are the paper's own lines above `leagueNews` on the News screen. A new context is an entry in `voice.json` and a condition in `seasonContexts`; a test fills every blank of every line.
- **Boss clubs**: each boss in `bosses.json` has `club` (what kind of club it is), `person` (a named coach or captain the paper and announcer talk about) and `answer` (what beats its trick). The third ringer offered after a boss is that person, with the club's talent.
- **A player's own conditional modifiers** (`Player.conditional`, `active` and `timed` in `src/sim/conditions.ts`; a team's are on `TeamState`): the simulation still carries them, sent with his other modifiers by `dress`, but nothing gives a player one today (temperaments were removed).
- **Nicknames** are earned once and kept on `PlayerRecord.nickname` (optional): a hat-trick or two goals against a rival (`earnNicknames` in `season.ts`), or long service (`closeChronicle`). `renamePlayer(f, id, name)` renames one of yours (`cleanName` says what a name may be).
- **Legacies** (`leaveLegacies` in `offseason.ts`): a retiring player of yours with enough seasons passes his talent to your youngest skater without one, or else joins the staff pool under his own name.
- **Found so far** (the `found` screen): every artifact, found or not, from `f.seen`; `f.wonWith` (optional) is the most handicap points a title was won with while holding each, written by `closeChronicle`.
- **What the town expects** (`src/core/expectation.ts`, numbers under `expectation` in `economy.json`): `startSeason` sets `season.expectation` from `nextExpectation(f)` (win some games, or reach the playoffs again if last season did). `seasonEndBills` multiplies the sponsorship by `expectationFactor(f)`: more for a target met, less for one missed. Nothing else depends on it; nobody is sacked. A weekly run has none.
- **Named leagues**: `leagueName(level)` in `prestige.ts` from `leagues` in `prestige.json` (one per prestige level, a test says so). `prestige(f)` writes the step up to `f.promotions` (optional), shown in the trophy room.
- **The cup**: `generateMap` marks one ordinary game stop in each region `Stop.cup` (a random stream of its own). `season.cup` is `{ won, alive }`: a tie won counts and pays `cupCurrency` more; a tie lost, or a region left without its tie won (`finishStop`), ends it at no other cost. `cupHeld(f)`, `isCupTie(f, stop)`. `closeChronicle` writes `cup: true` into the season's history line, and `coop: true` if `season.coop` (set by `App.tsx` when a season game is played with a second player); `clubRecords` counts both.
- **Conditions settled before a game** (`BEFORE`, `beforeFacts`, `settleBefore` in `season.ts`): a modifier's `when` may be `home`, `away`, `cupTie`, `rival`, `boss` or `targetMet`. `teamModifiers` and the season's `stat()` both settle them for the game waiting, so such a modifier may be on a stat the ice reads or one the season reads (`sponsors-patch` is `currencyGain` when `targetMet`). Their chip words are under `when` in `artifactLook.json`. Season stat added: `cupGain` (a cup tie's Pucks).
- **The newer boss tricks**: `sureFooted` (never knocked down; stagger times `check.sureFootedStagger`, in `check.ts`), `alwaysBraced` (blocks standing up: `braced` in `check.ts`; only a held brace slows him, in `world.ts`), a boss's own `mascotMisses` in `bosses.json` (enough that his mascot always comes at the opening; read in `season.matchup`), and conditional modifiers with a `label` on a boss (the Night Shift). Tells are drawn in `RinkScene.drawPlayers`. Tests in `tests/bossTricks.test.ts`: each trick, and that its stated answer works.
- **Measuring a season with the script is mostly counting bosses it cannot answer** (the Wall, the Marathon): adding bosses moves the title rate with no change in difficulty. See "The content round" in `docs/TUNING.md` before reading `measureSeasons` numbers.
- **Practice rink**: its pause menu has "Speed: Full / Half" (`RinkScene.setSlow`, the lesson's `slowScale`), to try a move slowly; not in a lesson, which slows itself. `MatchRules.practice` makes `createGame` hand back the scrimmage world (no clock, no faceoffs, never final). `playMatch({ practice: true })` from Exhibition loads two powerups free and runs the hints whatever the setting; leaving is the pause menu's "End game", and nothing is recorded.
- **Shake and flashes** (`Prefs.calm`, Settings): reaches `RinkScene` as `calm`. No camera shake, no camera flashes in the crowd (`Crowd.draw`'s last argument), and marks that pulse hold steady (`pulse()`). Drawing only; read when a game starts.
- **Puck setting**: `Prefs.bigPuck` reaches `RinkScene` as `bigPuck`; the size is `bigPuckScale` in `rinkLook.json`. It changes the drawing only.

## How gear and packs fit together

- `src/core/gear.ts`: the gear item, generation from the tables, the modifiers a piece gives, set bonuses, equip, level up, scrap. `src/core/packs.ts`: awarding a pack (contents rolled then, from the franchise seed and a counter), the pity timer, which pack a win earns, opening. `src/core/milestones.ts`: the season milestones and the tallies behind them.
- Tables: `src/data/gear.json` (slots, rarity table, which ratings each slot boosts, level costs, scrap values), `sets.json`, `perks.json`, `packs.json`, `milestones.json`.
- Gear lives on the franchise (`gear`, `packs`), not on players. A level costs cash and scrap sells for cash (`levelCost`, `scrapValue`: the tables in `gear.json` times `cashPerPoint`), booked on the lines `gearWork` and `gearSold`. On gear and players: `wornBy` on a piece names who has it on. Releasing a player goes through `releasePlayer`, which sends his gear back to the inventory.
- Gear uses the modifier system (as do staff and facilities, see below). A rating boost is a modifier with a stat like `rating.shooting`; `matchup.dress` applies those to the ratings (so the grade and cap hit, which come from the stored ratings, never move) and passes the rest (perks, set bonuses) to the simulation as that player's own modifiers through `TeamSetup.skaterModifiers` and `goalieModifiers`.
- Some abilities exist only for modifiers to switch on, and are off by default: `carrySpeedScale`, `chargedShotScale`, `passThrough`, `oneTimerScale`, `bigHitKnock`, `breakawaySpeedScale` (skaters), and `periodAutoSaves` and `gameAutoSaves` (goalies: a save that would have been a goal, once a period or once a game). The set bonuses in `sets.json` use the skater ones and `gameAutoSaves`.
- **Gear's strength was set by measurement** (`npm run measure -- gear [--part ratings|perks|sets]`, table in `docs/TUNING.md`): a whole team in a full Epic kit wins about 70% against an equal team with none, Legendary about 80%. Points a boost are fractions (`gear.json`); the rating a player gets is the rounded sum. Re-run the measurement after changing points, perks or sets: the three compound.
- `season.recordGame` awards the pack for a win and a Gold pack for each milestone the game completes.
- `tests/gear.test.ts` includes the 100,000-pack check of the rarity table and the pity timer.

## How the franchise loop fits together

- A season ends through `finishSeason(f)` in `src/core/offseason.ts`, never `endSeason` directly. In order: bank XP and level up (`xp.ts`), develop everyone who is not yours off the ice and age the league a year (`aging.ts`), roll retirements, tick contracts, then call `endSeason`. It fills `f.offseason` (the report, your `pending` expiring contracts, `leagueMoved`).
- **The off-season order:** `finishSeason` opens the free-agent pool at once (`openPool`: rookies, cheap players, prices) and you pick first. The other teams move in `leagueMoves`, which `beginSeason(f)` runs before it calls `startSeason`. Start a season through `beginSeason`; `startSeason` alone refuses until the league has moved.
- `decideContract(f, id, years | null)` settles one of your expiring contracts. When the last is settled (or there were none), `leagueMoves(f)` runs: AI teams re-sign or drop, fill their rosters from the pool (including players you let go), rookies arrive, and the pool is topped up and trimmed. `startSeason` refuses while contracts are pending.
- **Wages** are limited by the league cap alone (the owner's own payroll limit was removed). The careful automatic managers in `quickSeason.ts` keep a prudence of their own (`payShareOfValue`, `payShareOfCash` on a style in `offseason.json`), so the health check still says a sensible manager stays solvent; a person may spend up to the cap and into a fire sale.
- **Dead cap**: `releasePlayer` leaves `deadCapFor(...)` on `Team.deadCap` (optional field) for a player under contract, except in a fire sale; `payroll` counts it; `finishSeason` clears it. `roster.release` is the plain move and adds none.
- **Skill points**: `addXp(player, xp, true)` banks points on `PlayerRecord.points` (optional) for your players; `spendPoint` and `autoSpend` in `xp.ts` place them. The automatic manager calls `autoSpend`. `resignCapHit(player, f, years)` prices a contract by its length and his age.
- A cap hit changes only when a contract is signed (`resignCapHit`, and when an AI team signs). `regrade` in `xp.ts` updates overall and grade and leaves the cap hit alone.
- `src/core/trades.ts`: `tradeValue`, `evaluateTrade` (the reason is shown to the player), `trade`. A team will not give up a player who is better today unless what comes back is worth `futurePerPoint` more to it for each point of overall it loses (`offseason.json`); `tests/fleece.test.ts` plays a manager who does nothing but trade and checks what he can gain. `src/core/prestige.ts`: `canPrestige`, `prestige`, `prestigeEffects`, and the jersey colours. Prestige reaches games through `matchup()` (opponent ratings and AI level) and packs through `rarityTable(boost, floor)`.
- Tables: `src/data/xp.json`, `aging.json`, `offseason.json` (rookies, pool, trade values, quick-game values), `prestige.json`.
- `src/core/quickSeason.ts` is for health checks only: an automatic manager (`autoOffseason`), games settled from strength (`quickResult`) and `leagueSnapshot`. `tests/harness/seasons.ts` and `npm run seasons` use it; the numbers are in `docs/TUNING.md`. Re-run it after any change to the XP, aging or off-season tables.
- Save version 4 adds `xp` and `level` per player and `prestige` and `offseason` on the franchise.
- Screens: off-season report, expiring contracts, trade (team, their player, your player, confirm), prestige and jersey colour, all in `App.tsx`. The jersey colour reaches the rink through `playMatch({ homeColour })`.
- Tests are in `tests/franchise.test.ts`, including 20 seasons from 20 seeds.

## How the club side fits together (cash, staff, facilities, scouting, mascot)

- Cash only moves through `book(f, line, amount)` in `src/core/ledger.ts`, so the income statement always adds up to the change in cash. `f.ledger` is this season so far; `f.books` holds every closed season.
- `src/core/economy.ts`: what each game pays (`bookGame`, called from `season.recordGame`), the end-of-season bills (`bookSeasonEnd`, called first thing in `finishSeason`), franchise value, and the fire sale (`inFireSale`, `playerSalePrice`, `canBailOut`, `bailOut`). `startSeason` refuses with cash below zero.
- `src/core/facilities.ts` and `src/core/staff.ts` each turn what you own into modifiers; `src/core/club.ts` joins them (`clubModifiers`, `clubStat`). The stats are `xpGain`, `xpGain.F|D|G`, `agingDecline`, `resignCost`, `scouting`, `ticketRevenue`, `merchRevenue`, `sponsorRevenue`, `mascotPower`, read by the rules, and `drainScale` and `recoverScale`, which reach the ice through `teamModifiers`. In the data a "mul" is written as a rate per level or grade step; `scaleModifiers` in `src/sim/modifiers.ts` turns it into a multiplier.
- On the ice the club gives: the medical wing (`drainScale`, `recoverScale`), the training centre (`accuracy`, `passSpreadDegrees`), and at home the arena (`homeIceModifiers` in `facilities.ts`, added by `teamModifiers` when `isHomeGame`). Prestige gives `prestige.freeBuilds` (a facility level `build` does not charge for) and a bigger sponsorship share. `finishSeason` writes what the club did into the report's news as lines starting "Your club:".
- The mascot is a visitor for one period (`src/sim/mascot.ts`): `rollMascots` runs at the opening faceoff and at the start of each later period. A team rolls at the opening, or when it trails by `trailBy` goals (never in overtime); the chance is `baseChance` plus `missStep` for every miss in a row (`mascot.json`). On a hit he takes over one dressed skater (`MascotSetup.slot`: the lowest rated) by swapping that player's `baseFx`, talents and stats, and gives them back at the period's end. `isMascot(world, p)` says a player is him now; `ownStats` gives the replaced skater's own line. The rolls use `world.rng.fork(...)`, so a game without mascots is unchanged. `GameResult.mascots` carries his stat line, arrivals and the misses after the game; `season.recordGame` writes the misses back (`f.mascot.misses` for you, `season.mascotMisses` by opponent). Simulated and exhibition games have no mascots.
- `src/core/scouting.ts`: `potentialRange`, `hiddenFreeAgents`, and `signPlayer`, which the menus and the automatic manager use instead of `roster.sign` (it refuses hidden players and notes the signing in `f.offseason.signed`, which is what stops a fire-sale exploit).
- `src/core/mascot.ts`: power (rating and talents only, not the chance), `dropInChance(misses)`, AI and boss mascots, `sitsFor` and `mascotSetup` (what the simulation is given). `season.matchup` puts each side's on `setup.mascot` and reports the odds in `Matchup.mascots`. XP and milestones never see him: his goals are only in `GameResult.mascots`.
- Talents run in `src/sim/talents.ts` from `src/data/talents.json`: a skater's `talents` list comes from `TeamSetup.skaterTalents`. Timed ones reuse the boost code (`startBoost` in `powerups.ts`); the spin move hooks into `check.ts`.
- Tables: `src/data/economy.json`, `facilities.json`, `staff.json`, `scouting.json`, `mascot.json`, `talents.json`. Manager styles for the health check are in `offseason.json` under `quick.styles`.
- Save version 5 adds `cash`, `value`, `ledger`, `books`, `staff`, `staffPool`, `facilities`, `mascot`, `tenure` and `offseason.signed`. Version 7 drops `tape` (it becomes cash) and adds the two gear lines to every ledger.
- Screens: Finances, Staff (and hiring), Facilities, Mascot, in `App.tsx`; reachable in and out of season.
- Tests are in `tests/club.test.ts`, including 20 seasons under three manager styles. After changing any economy number, run `npm run seasons` and update `docs/TUNING.md`.

Standing (`speed` 0) or gliding (`PoseInput.glide`) he takes no strides, so the scene uses one picture for each. `Effects.gliding(id)` is true once a player has been losing speed for `glideAfter` seconds (`glideDrop`, under `effects` in `rinkLook.json`), and his stride waits meanwhile. A goalie is always side-on. **Eight ways and a lean** (chosen by the owner on 2026-11-17 from four candidates): on a diagonal `viewOf` gives `quarter` (heading down the screen) or `quarterBack` (up it), with a hysteresis of its own (`quarterEnter`, `quarterLeave`); the picture is the square-on view (front or back) turned toward his heading: every piece is drawn narrower by the cosine of `figure.quarter.yaw`, and carried across by its depth (`figure.quarter.depth`, by tag: face, gloves and skates the most), done in `figure()`. The first version squeezed the side view; the owner asked for a real three-quarter. The sprite is also turned a few degrees into his heading (`leanDegrees`, scaled by speed, from `leanFromSpeed`; not when square on, fallen, cheering or a goalie), and the stick is turned with it so the blade stays on the puck. A turn to the other side or another view is a quick squeeze of the sprite (`turnSeconds`, `turnSquash`), not one sudden change. Seen from behind, his number is drawn on his back (`figure.backNumber`). **Other poses**: `PoseInput.fallen` is a skater flat on the ice after a big hit (`sprawled`: a pose of his own, the sprite is not turned over); a goalie moving across his crease shuffles his pads (`figure.goalie.shuffle...`) and the action `kick` thrusts a pad out, used by `Effects` for a save made on the move. **Detail**: a player's jaw follows his portrait's face shape (`PlayerLook.face`, `figure.faces`), a captain has a patch on his chest from the front, home gloves are the club's second colour, and the builds differ more than they did. **The goalie** (rebuilt 2026-11-17 after the owner saw the catching glove drawn behind his back; stance A of six candidates, numbers in `figure.goalieStyles[0]` and `figure.goalie`): he faces the shooter with his knees bent, real leg pads (`padLeg`), the glove open ahead of his chest on the far hand and the blocker and stick low in front on the near one. A test says both hands are in front of him in every pose: keep it that way. `PoseInput.alert` (0, 0.5 or left out) is how near the play is: with the puck at the other end he stands taller with the glove down, and sets as it comes (`alertNear`, `alertFar`). His actions (`GOALIE_ACTIONS`): `glove` and `kick` from saves, `slide` when he crosses his crease faster than `slideSpeed`, `post` when the puck is behind the goal line or close at a sharp angle, `rise` for a moment after the pads come up (set by `Effects`). The scene works `alert`, `slide` and `post` out from the puck and his speed; they are drawing only. **Skaters** have body E of six candidates (lower over the stick, a longer stride, a wider stance), and two more actions: `shot` (the follow-through, from the shot event) and `stop` (braking harder than `effects.stopDrop` from `stopFromSpeed`: skates out ahead, leaning back). Candidates are drawn by adding a list of styles to `rinkLook.json` and a temporary `variant` on `PoseInput`, shown on the art sheet; both were removed once the owner chose. **Looks**: `src/core/playerLook.ts` works a player's look out of the player himself, nothing stored: skin, hair and beard from his menu portrait (`portraitOf`), a build from his kind (`buildOf`, table in `src/data/playerLook.json`); `teamLooks` gives a team's in dressed order with a captain's band on its best skater. `matchView` passes them to the scene as `RinkSceneOptions.looks`; the simulation never sees them. A mascot on the ice is drawn with ears and no helmet. **Poses**: `PoseInput.action` is a pass follow-through, a poke, a hit, a deke, a tired glide, or a goalie's glove save; `Effects.action` holds the ones that come from events for a moment (`actionSeconds`), the rest come from the player's state in `RinkScene.drawPlayers`. `cheer` is the scorer, `mateCheer` his team-mates. `RinkScene.drawPlayers` has a pose painted once into a canvas, then rounds each player's pose to a few steps, keeps one texture per pose and look (`figureKeys`, repainted on resize, the longest unused dropped past `maxTextures`), and shows it on that player's sprite, flipped to face left and sorted by depth. Shadows, the control ring and sticks are on the graphics layer below the sprites; the puck and sparks on the one above (`top`). `src/ui/FigureArt.tsx` paints the same figure with the same painter on a canvas, for the art sheet. Do not go back to painting shapes with Phaser graphics every frame: that cost about 6 ms a frame. Each team has two kits (`figureColours(..., kit)`): its colour at home, white on the road; `RinkSceneOptions.whiteTeam` says who wears white, and `playMatch({ userAtHome })` sets it from the schedule (`isHomeGame`). The ring under the controlled player and the arrow over the puck carrier (either team) are under `reticle` in `rinkLook.json`.
- Touch: `src/game/touch.ts` holds the shared touch state and turns it into an `InputFrame` (pure, tested); `src/ui/TouchControls.tsx` is the overlay that writes it; `InputReader` merges it with the controller and keyboard.
- Crests: `src/core/crest.ts` works a team's badge and jersey design out of its name (lists in `src/data/crests.json`, outlines as point lists in the same file). `src/ui/Crest.tsx` draws it as SVG and `src/game/drawCrest.ts` on the ice from the same points.
- On-ice effects are in `src/game/effects.ts` and the crowd in `src/game/drawArena.ts`; both only read the simulation. `RinkScene` hands them the events `step()` returns. Numbers are under `effects` and `arena` in `rinkLook.json`. Randomness there uses `createRng`, like everything else.
- Sound: `src/game/soundMap.ts` says which event makes which sound (pure, tested); `src/game/audio.ts` synthesises each from its recipe in `src/data/audio.json` and runs the crowd bed (the skating sound was removed after the owner listened). `gameAudio.played` counts what was asked for, which is how to check sound without hearing it; to measure a sound, render `playSound` into an `OfflineAudioContext` in the browser (the test environment has no audio).
- Device preferences (sound, volume, rink detail, on-screen controls) are in `src/ui/prefs.ts`, stored apart from the save.
- Pack opening is `src/ui/PackOpening.tsx`; all motion is CSS at the end of `src/style.css`, switched off under `prefers-reduced-motion`. Do not name a class `up` or `down`: those are global colour classes.
- **Seeing a screen that is slow to reach.** Write a temporary test (not kept) that walks a franchise there with the real rules (`startSeason`, `travel`, `recordGame` with a made-up result, `pickArtifact`, `finishSeason`, `autoOffseason`, `beginSeason`) and writes `JSON.stringify(toSave(f, date))` to a folder inside the project; in the dev page, fetch that file, `put` it into IndexedDB (`hockey-roguelite`, store `saves`, key `franchise` or `weekly`) and reload. Remove the folder afterwards. This is how the ringer offer, a rival game, the cup, legacies and the weekly result were looked at.
- **Seeing the game when the app window is hidden.** Ordinary screenshots time out then. What works: in the page, serialise the DOM into an SVG `foreignObject`, draw it to a canvas, and POST the PNG to a small local Node receiver; for the rink, step a frame (`__game.loop.step`) and copy `__game.canvas` in the same task. Then read the PNG file. The SVG's size sets the viewport, so 844 x 390 gives a phone-landscape layout whatever the real window is. To get the rink itself at phone size, set the browser tab's viewport to 844 x 390 before starting a game. Add `*{animation:none !important}` to the copied styles, or a screen is caught mid-animation.

## How the on-ice game fits together

- `src/sim/world.ts`: `createGame(tuning, seed, options)` starts a full game; `createWorld(...)` starts a scrimmage (endless play, no clock, faceoffs or line changes; used by most tests). `step(world, humanInput, tuning)` advances either by one fixed step of 1/60 second and returns the events that happened. Nothing else advances the game.
- Game rules are in `src/sim/match.ts`: periods, the clock, the faceoff duel, overtime, and `gameResult(world)`, which later phases use for XP and milestones. (It is not called `game.ts` because the folder rule test treats `game` as the rendering folder.)
- 14 players are dressed: for each team, ids run from `team * 7`: six skaters (the first three are line 1, the next three line 2; `slot` 0 is the centre), then the goalie. `onIce` says who is playing. Use `skatersOf`, `availableSkaters` (not heading to the bench) and `onIce` from `team.ts` rather than looping over `world.players`.
- Lines, the bench and fatigue are in `src/sim/lines.ts`. A line change sends skaters to the bench door, where each is swapped for his opposite number; the puck carrier goes last. Changes are automatic at safe moments, and the line-change button forces one.
- Humans and AI use the same mechanics: both produce an `InputFrame`. `src/sim/ai.ts` is a five-state machine (attack, support, chase, defend, backcheck). In the attacking zone (`inZone`) the skaters without the puck take posts (`postsFor`, `postSpot`: net-front, wing, point) instead of following the carrier, and a carrier beyond normal range may plant his feet and take a long shot (`AiMemory.plant`). Positioning numbers and the easy-to-hard ranges are in `src/data/ai.json`. Difficulty changes thinking only, never physics.
- **Checking** (`check.ts`): `stepChecking` tracks the button and throws on release through `resolveCheck(world, p, charged, ...)`. A tap is a poke; held for `check.bodyHoldSeconds` it is a body check if the carrier is within `bodyRange`. `Player.checkClosing` keeps the fastest closing speed during the hold, which is what `minClosingSpeed` and the big hit are judged by. The AI holds through `AiMemory.checkSteps`. The limits a check is judged by come from `checkRules(world, p, t)`: the skater the human controls gets the easier `checkAssist` ones (wider poke arc, better odds, shorter hold, longer reach, a short wait after a miss); read limits through it, not from `t.check`. The human's shots get `aimAssist` (aim at the open corner, and `spreadScale` less scatter); aim nearer the post, not further in, to help. A one-timer is steered at the net whatever the stick says (`assistedAim(..., firstTouch)`): it is let go as the pass arrives, with the stick still pointing where he was skating, and without this it flew off backwards.
- **The season's own powerup**: `signatureOffer(f)` draws three for the season about to start; `startSeason(f, { signature })` keeps the one chosen on `season.signature`. `matchup` puts it on the first button with `recharge` (`signatureRechargeSeconds`); `PowerupSpec.recharge` makes `usePowerup` leave it on its button and set `TeamState.powerupWait` (boost seconds plus recharge), counted down in `stepPowerups`; it is never in `powerupsUsed`. `setLoadout` refuses slot 0 while there is one. The second button is loaded from the bag as before.
- **Pucks at each end of a season**: a season starts with `startingCurrency` Pucks (`season.json`), so the first shop reached has something affordable; `leftoverPack(f)` is the pack the Pucks left at the end are worth (`leftoverPacks`, best tier first), awarded by `finishSeason` with a line in the report. Never in a weekly run. The reason: most Pucks are won after the last shop (bosses and the playoffs), and a stand-in that buys everything sensible still ended a season with half its Pucks. `npm run measure -- seasons --shopper` is that stand-in; without the flag it buys one powerup a shop, as it always did, so old numbers still compare.
- **The shop**: `shopArtifact`, `buyShopArtifact` (one artifact per shop, kept on `Stop.shelf`, drawn from its own stream), `rerollPrice`, `rerollShop` (`Stop.rerolls`, prices in `rerollPrices`), `buySecondChance` and `insuranceLeft` (a bought second chance on `season.secondChance`, plus the `bossInsurance` stat of artifacts less `season.insuranceSpent`). Every price goes through the `shopPrice` stat.
- **A second man to the puck** (`planDefend` in `ai.ts`, `matePressFromX` and `matePressGap` in `ai.json`): when the nearest defender is the one a person controls and he is not on the carrier, the nearest AI team-mate presses too. `tests/harness/defence.ts` (`measureDefence`) counts what a person's team gives up; use it after changing defending.
- **Rumble**: `src/game/rumbleMap.ts` (pure, tested) says which buzz each player feels for a batch of events, from the table under `rumble` in `controls.json`; `src/game/rumble.ts` plays it on the seat's controller (`padIndex`) or the phone, silently doing nothing where there is no support. `rumble.played` counts what was asked for. `Prefs.rumble`.
- **Feats** (`src/core/achievements.ts`, `src/data/achievements.json`): `earnAchievements(f)` marks the ones now done on `f.feats` (called at the end of `recordGame` and, for the ones read from the history, in `finishSeason` after `closeChronicle`); `progress(f, a)` is how far along one is. What they open: `featJerseys` (added by `unlockedJerseys`), `charterOpen` (a charter with `locked: true` in `charters.json` needs its feat; `startSeason` falls back to the standard one, and the weekly draw leaves them out), `extraPowerupChoices` (added in `signatureOffer`). `f.bossesBeaten` lists boss clubs beaten once. A new feat is a data entry of an existing kind.
- **Game length**: `periodSecondsOf(f)`, `setPeriodSeconds` (choices in `season.json` `periodLengths`; the standard is stored as nothing). `playMatch({ periodSeconds })` puts it on a copy of the tuning.
- **Boss introductions**: `playMatch({ intro })` renders `src/ui/MatchIntro.tsx` into `#intro` over the rink and holds the scene paused (`introOn`) for `introSeconds` or until a press after `introGraceSeconds`.
- **The town rallies** (`rallyOffered`, `season.rally`, `rally` in `season.json`): when the last season ended on strikes, the set-up screen offers one more strike and one more powerup for the season about to start (`startSeason(f, { rally: true })`); the modifiers join the charter's in `seasonSetupModifiers`. Never in a weekly run. After such a season the sponsor does not dock the sponsorship for the missed target either (`struckOutPenalty` in `economy.json`).
- **A boss loss ends the run** only under the "One meeting" handicap (`oneMeeting` in `charters.json`, the season stat `bossLossEnds`, read by `bossLossEnds(f)`): `settleGame` ends the season as `struckOut`. Without it, on every difficulty, a boss loss is a strike and a rematch. The shop's second chance is sold only to those who took the handicap.
- **What opens later** (`src/core/opening.ts`): `opened(f, 'setup' | 'weekly' | 'tactics')`. Charters and handicaps, and the weekly run, open after a first finished season; tactics and line shifts once a boss has been beaten (or a season finished). Worked out from `f.books` and `f.bossesBeaten`, nothing stored; a weekly run has everything open. The screens leave the rows out, and `playMatch({ noTactics })` leaves tactics out of the pause menu.
- **Removed on 2026-11-16, by the owner's choice** (see `docs/DECISIONS.md`): the passing chain, the opponents' goalie pull (a person may still pull his own), the Press forecheck, temperaments, artifact stickers (loan, pricey), bounties, tape, and the owner's payroll limit. Do not bring one back as a side effect of other work.
- **The first start** (`firstRun` in `useApp`, set when there was no save): the title's button goes to the difficulty screen in its `first` form (Rookie suggested: `suggestedDifficulty` in `season.json`), then to `switching` (who changes the skater you control), then home. Both screens and the page "How you are helped" (`assists`, under Settings: the help a person's team gets, worded from the numbers in `physics.json`) are in `pages/welcome.tsx`. If an assist's numbers or meaning change, change its sentence there.
- **The help as settings** (`src/core/assists.ts`, `assists` in `season.json`): four kinds (aim, pass, check, goalie), each at a step (full, part, off; pass has no part). `assistSteps(f)` is the franchise's own choice (`f.assists`, optional) or else what its difficulty gives (`assists` on a difficulty; left out means full, which is what every difficulty gives today). `assistStrengths(f)` goes to a game as `playMatch({ assists })`, and `assistTuning` multiplies the four `strength` numbers on a copy of the tuning. `setDifficulty` clears the choices. In the simulation a strength between 0 and 1 means: aim goes for the corner on the side the stick points (at 1 the game picks the open corner; never blend the two, half-way is the goalie's chest), check limits are part-way between plain and helped, the goalie's help is that share. Screen: `assists` in `pages/welcome.tsx`.
- **A grace for an early shot** (`grace.seconds` in `physics.json`, `Human.earlyShoot`): shoot let go just before a pass reaches the person's team still counts when the puck arrives. Only shoot, and only with a pass on its way: a tap of pass in flight is the give and go.
- **The last man back** (`planDefend` in `ai.ts`, `guardFromX` in `ai.json`): on a person's team, with the carrier over that line, the AI team-mate nearest the spot between carrier and net goes there before anyone presses. **Any other team** does the same against a carrier who is leading the rush himself (none of his team-mates nearer the net), until he reaches the zone, where the slot guard takes over; opponents below `holdBackFrom` (the easiest difficulty) do not. Holding a man back any longer, or pulling the chaser off the carrier, frees the pass to the man at the net: both were measured and taken out (`docs/TUNING.md`, "The lone carry-in").
- **AI shot blocking** (`wantsBlock` in `ai.ts`, `blockRange`, `blockSettle` and the level range `blockEagerness` in `ai.json`): the last man or slot guard, once in the lane between the carrier and the net with the carrier in range and not close, holds the check button (`AiMemory.brace`) so that he is `braced` and stops the shot. `aiInput` keeps the button down while their shot is on its way. Both teams' AI skaters do it, a person's team-mates included.
- **A marked one-timer strays** (`oneTimerCrowd` in `world.ts`; `oneTimerCrowdRange`, `oneTimerCrowdFull`, `oneTimerCrowdDegrees` under `shot`): a first-touch shot gets extra scatter for an opposing skater near the shooter, none beyond the range and the most inside the full distance. For anyone, a person or the AI. It is what brought passing back toward carrying (the passer from 6.1 goals a game to 5.2, the script unchanged) after six other ways were tried and taken out: see "The lone carry-in" in `docs/TUNING.md` before trying a seventh.
- **Goalies read a pass** (`goalieTarget` and `stepGoalie` in `goalie.ts`; `passRead`, `passSlide` in `physics.json`): while a pass is on its way to an opposing skater the goalie plays the angle of the receiver, without waiting his reaction time, and moves `passSlide` times as fast. Stepping further out (`challengeDepth`) helps against the lone carrier and hurts against the pass: it was measured and left where it was.
- `npm run measure -- carry [--player script|passer|novice]` says where a stand-in's shots and goals come from, how often a defender is in the lane or down, and how many shots are blocked; `npm run measure -- gear` what a full kit of each rarity is worth. Run `carry` for the script and the passer after any change to defending or goalies: the two must be read together.
- **The mercy rule**: `MatchRules.mercy` ends a game in `afterGoal` when a goal makes the lead that big. `season.matchup` sets it (`mercyLead` in `season.json`) for ordinary games only; a boss and a playoff game are played out.
- **The Marathon's press tires its own skaters** (`drainScale` 0.85 on the boss, was 0.4): with skaters that barely tired, no stand-in beat it more than about one game in four however it passed; at 0.85 the script wins about 55% and the passer 65%. Its card says to get the puck out of your end and make them skate. `npm run measure -- seasons --bosses` lists every boss game of the seasons played, by region and boss.
- **Bosses by region**: a boss with `minRegion` in `bosses.json` is not drawn for an earlier region (`generateMap`). The Wall and the Marathon have 1: the script cannot beat them and no person has shown their answers work.
- **How each goal was scored**: `world.lastShot` and `world.goalNotes` (who, whether his path was clear, a one-timer, how far); `GameResult.goals`; `src/core/goalLog.ts` turns them into the two lines on the end-of-game screen.
- **Frame times**: `RinkScene.frameStats()` (the last `frameWindowMs` of play); the pause menu shows it at the top.
- **Old saves**: `tests/fixtures/save-v6-*.json` are real saves kept as they were written; `tests/oldSaves.test.ts` loads and plays them on every run. When `SAVE_VERSION` goes up, leave them and add one of the new version.
- **A person's AI team-mates** get part of check assist: better odds (`checkAssist.matePokeBonus`, `mateBodyBonus`, through `checkRules`) and more readiness to check (`mateCheckBoost` in `ai.json`, applied at the top of `think`). Nothing else of the person's help.
- **Goalie assist** (`goalieHelped` in `goalie.ts`, numbers under `goalieAssist` in `physics.json`): the goalie of a team with a human on it reacts sooner (`reactionScale`) and comes further out (`challengeDepth`) while the opponent carrying the puck, or who has just shot it, has a clear path (`clearAhead`). Nothing for an all-AI team. It was set by whole-game measurement (see `docs/TUNING.md`): 0.6 was far too strong.
- Moves beyond skate, pass, shoot and check: a **one-timer** (shoot held as a pass arrives fires first-touch: `oneTimerArmed` set in `contact.ts`, released in `world.ts`; any shot inside `shot.oneTimerWindow` of receiving a pass is a full wind-up times `shot.oneTimerPower`, and gear's `oneTimerScale` multiplies it); a **deke** (the switch button while carrying: `stepDeke` in `world.ts`; `dekeAngle` in `src/sim/deke.ts` sends it round the nearest defender and `wrongFoot` slows him; a check during `Player.deke` fails in `check.ts`; it never refuses for lack of stamina); a **big hit** (a body check at `check.bigHitClosingSpeed` or more sets `knockedDown` and a longer stagger); and rebounds pulled toward the slot (`makeSave`). The goalie steps out on a straight-on carrier (`goalie.challengeDepth`) and meets a shot at the depth he stands at.
- **The steal at the wind-up**: in `resolveCheck`, a check on a carrier winding up with `unstoppableCharged` always succeeds (unless he dekes), and the event carries `windUp`. **The horn waits**: `tickClock` holds a period open at 0:00 while `shotInFlight` (up to `period.shotGraceSeconds`).
- **Shot fake** (`src/sim/fake.ts`): pass pressed during a wind-up cancels the shot (`stepFake` returns the input with pass taken out while it stays down); the goalie's `bitten` timer holds him still in `stepGoalie`. **Shot block**: `braced(world, p, t)` in `check.ts` (check held a while, without the puck, the carrier not close); a braced skater is slowed in `world.ts` and stops an opponent's shot in `resolveLoosePuck` with a `block` event. The AI does neither.
- **Floating words and the pass mark**: `src/game/floatWords.ts` (pure, tested) says which events get a word (`wordsFor`) and which conditional items have just come into force (`newlyInForce`); wordings and timing are under `floatWords` in `rinkLook.json`. `passPreview` in `src/sim/pass.ts` is the team-mate a pass would go to now; the scene draws a diamond under him. Player two's ring is doubled.
- **Replay** (`src/game/replay.ts`, tested in `tests/replay.test.ts`): `Recorder.before(world, input, input2)` is called before every live step; it keeps a copy of the world a second (`copyWorld`: `structuredClone` plus `rng.clone()`) and the inputs for the last few seconds. `clip(from, to)` gives a world to run again and the inputs to run it with. After a goal's celebration `RinkScene` cuts the clip and, if `Prefs.replays`, shows it at half speed in place of the game (`stepReplay` swaps `this.world` for the copy while drawing). `goalOfTheGame` picks one for the summary, which Shoot watches again. A replay re-runs the simulation, so anything that makes the simulation depend on something outside the world, the inputs and the tuning would break it: the test compares a re-run with the live game step for step.
- **Hints**: `src/game/hints.ts` (pure, tested) says which move is on for the human now (`hintsThatApply`, `hintFor`) and which event counts as doing one (`hintDone`); texts and timing in `src/data/hints.json`. `RinkScene` shows one line where the goalie-pull prompt goes. On or off is `Prefs.hints`; the counts are stored apart under `hockey-hints` (`loadHintCounts` in `prefs.ts`) so a settings change can never wipe them. A new move needs an entry in `hints.json`, a condition and an event.
- **The first skate** (`src/game/lesson.ts`, `src/data/lessons.json`, `src/sim/drill.ts`): a lesson run on the practice rink. `playMatch({ lesson: true })` makes a practice world; `RinkScene` keeps a `Lesson` (which step, how many done), counts each step of the simulation toward it (`lessonAdvance`), shows `lessonLine` where the hints go and the step's `why` where the commentary goes, and ends the game a moment after the last step. `stageDrill(world, t, 'loose' | 'attack' | 'defend')` sets a situation up; the scene calls it between steps (never inside one), after a goal, and when the puck has been with the wrong side for `resetSeconds`, and then holds the play still (`lessonHold`) until the person touches the controls. Hints and commentary are off during it. It is offered once at the first start (the `firstSkate` screen, after `switching`) and is always under Exhibition; both are in `pages/teach.tsx`. A new step is a data entry plus a line in `doneNow`. There are two skates (`LessonId`): the first, and a second for the later moves (deke, fake, give and go, saucer pass, block), under Exhibition; `playMatch({ lesson: 'first' | 'second' })`. A step's `say` names controls as `{move}`, `{shoot}`, `{pass}`, `{check}`, `{switch}`, filled in by `sayFor` for what is being played with (`InputReader.device()`: controller, keyboard or screen; names under `controls` in `lessons.json`). On the steps in `slowSteps` time runs at `slowScale` while the person's own pass is on its way, and on any practice rink a gold ring is drawn round the man a pass is going to.
- **What ratings are worth** (`src/core/ratingWords.ts`, `src/data/ratingWords.json`, the `ratingWorth` screen under Settings): what ten points of each rating change, worked out from `ratings.json` and `physics.json` each time, so it cannot go stale. A new effect of a rating needs a wording in `ratingWords.json` (a test says so).
- **Signs on the rink** (the `signs` screen under Settings, `src/data/signs.json`, `SignArt` in `pages/teach.tsx`): every mark the rink draws, with a small drawing and what it means. A new mark on the ice needs an entry there, and a new kind of drawing a case in `SignArt` (a test lists the kinds).
- **Why a move missed** (`FailWatch` in `src/game/hints.ts`, wordings under `fail` in `hints.json`): with hints on, words rise from the person's skater when a check was thrown from too far (`whiff` event, only ever sent for a person's skater), facing the wrong way (`whiff.turned`), or from behind the carrier (`check.miss`), and when a shot just after taking a pass was not a one-timer. On the practice rink a thin circle shows the poke's reach. The basics have hints too (`shoot`, `pass`, `switchTo`); a switch has no event, so the scene counts it.
- **Momentum** (`src/sim/momentum.ts`): `TeamState.heat` fills from goals, big hits, one-timers, saves, blocks, a poke check that takes the puck (`steal`) and a deke that slips a check (`evade`); full starts the `onFire` boost through `startBoost`. **Tips and screens** (`src/sim/tips.ts`): `screened` lengthens the goalie's reaction in `goalie.ts`; `stepTips` redirects a shot past a teammate near the net. **Give and go**: `world.human.giveGoOffer` is set when the human passes; a second press of pass makes it `giveGo`, `updateControl` and `givePuck` then keep control on the passer, and the receiver's AI returns the puck through `AiMemory.passTo`. **Goalie pull** (`lines.ts`: `mayPull`, `pullGoalie`, `returnGoalie`, `stepPulls`): the goalie goes off the ice and a bench skater comes on as `TeamState.extra`; line changes are held while pulled; `freshLineOn` undoes it at any faceoff. `InputFrame.pullGoalie` is the View button or G.
- **Line shifts**: `Lineup.heavy` (optional) names the line that plays more; `dress` passes it as `TeamSetup.heavyLine`, and `autoChange` in `lines.ts` shifts the energy level at which each line changes by `energy.heavyShift`.
- **The Wall's shields are spent by shots on goal** (`shieldBurn`, a goalie effect; `shieldsLeft` in `goalie.ts`): with it, a save the goalie makes by himself uses up one of the period's automatic saves, so the card's "burn them with quick shots" is true. Without it (the Guardian angel artifact) an automatic save waits for a shot that beats him. Until 2026-11-17 the Wall worked the second way and could not be answered.
- **Boss tricks** are abilities switched on by modifiers in `bosses.json`: `periodAutoSaves`, `gainBurst`, `alwaysKnockdown`, `fullPress`, and `unstoppableCharged` (given to the best shooter through the boss's `star` list). A boss may also give every skater talents (`talents` in `bosses.json`), and `periodStartHeat` fills its momentum meter at the start of each period (`momentum.ts`). The scene draws each one's tell.
- The scene (not the simulation) freezes for a beat on a big hit or a goal and runs in slow motion after a goal (`effects` in `rinkLook.json`); the scorer's figure cheers.
- **Rinks** (`src/data/rinks.json`, `src/core/rinks.ts`): a rink is a name, a sentence, tuning overrides by group and name, and `MatchRules` (`firstTo`, `oneLine`). `rinkTuning(base, rink)` gives a copy of the tuning with the rink's numbers; `matchView.playMatch({ rink })` puts that on top of the tuning panel's and hands the rules to `createGame` through `WorldOptions.rules` (kept on `world.match`). In a season some ordinary game stops and every boss stop carry `Stop.rink` (set in `generateMap` from a random stream of its own; a boss's is `rink` in `bosses.json`); `Matchup.rink` passes it on and a win on a variant rink pays `seasonBonus` more. A new rink is a data entry: run it through 100 all-AI games first (the AI's positions are fixed distances, tuned for the standard rink).
- **Shootout** (`src/sim/shootout.ts`): `WorldOptions.rules.shootout` makes `world.rules` "shootout": turns of one skater against the other goalie from centre, `attemptSeconds` each, settled after `rounds` each or carried on in pairs. It uses the ordinary play step with nobody else on the ice; `stepShootout` ends an attempt, `nextAttempt` sets up the next. Exhibition only (`playMatch({ shootout: true })`).
- **Tactics** (`src/sim/tactics.ts`, numbers in `ai.json` `tactics`): `TeamState.tactics` tells a team's AI skaters how to forecheck, attack and defend; `ai.ts` reads it in `think` (press, sit back), `styleOf` and `planSupport` (rush, cycle, crash) and `planDefend` (collapse, man-to-man). Balanced, or null, is the play of before. Your lineup carries them (`Lineup.tactics`, optional); `dress` passes them; the pause menu changes them for the game in progress through `RinkScene.setTactics`. (The Press forecheck was removed: a stored lineup that had it reads as Balanced.)
- **How the styles differ** (fields on a style in `ai.json`, all read in `ai.ts`): `netRun` (the first man without the puck races to the front of the net before the zone, as a person's own line-mate does), `carry` (how long a carrier holds the puck, times `maxCarrySeconds`), `check` (times `checkEagerness`, in `think`) and `chasers` (how many go after a carrier in his own end: `chasersOf`, in `planDefend`). They were set so each style wins 45 to 55% against the others and against a team with none: run `npm run measure -- styles` after touching them.
- **Late in the last period the score tells an AI team what to do** (`lateMood` in `ai.ts`, `late` in `ai.json`): a goal or more behind it pushes (two chasers, quicker to check); ahead it protects (the Sit back forecheck and the Collapse defence). Never a team a person plays on, never in overtime. It is not the goalie pull, which stays removed.
- **A second man to a loose puck** (`scramble`, `chooseState`): a loose puck within `scrambleRadius` of either net is chased by a team's nearest two, the second only from within `scrambleReach`. On a person's team that second man is an AI line-mate going for the rebound.
- **Getting open** (`openSpot`): a man without the puck whose spot is covered, or whose lane from the puck is blocked, tries a step to either side and then a step out from the net (`getOpenShift`, `getOpenBack`). A person's man at the net does it too once the puck is in the zone.
- **The stretch man** (`planSupport`; `stretchX`, `stretchAgainst`): on a team a person plays on only, with the puck in its own half and two or more opponents in that half, the first helper goes over centre and waits for the long pass. Given to AI teams as well it cost them a defender and the script scored 0.7 more a game, so they do not have it. The easiest opponents (below `holdBackFrom`) play no style extras and do not read the score.
- AI teams have a **style** (`rush`, `cycle`, `dump` in `ai.json`): `src/core/playStyle.ts` picks it from the team's name, `dress` puts it on every team but the user's, and `styleOf` in `ai.ts` reads it. In defence one free defender guards the slot between carrier and net; in support a covered teammate slides until his passing lane is clear.
- Ratings (0 to 100) become physical effects in `src/sim/ratings.ts` from the table in `src/data/ratings.json`. A skater rated 70 gets exactly the plain `physics.json` values. To make a rating worth more or less, steepen or flatten its range but keep the value at 70 where it is (ten points is now about 2 to 4%).
- **Player kinds and talents** (`src/core/playerKind.ts`, `src/data/playerKinds.json`; each kind lists the `talents` a new player of it may get): `kindOf(position, ratings)` works a player's kind out from his ratings (nothing is stored); `generatePlayer` leans a new player toward a rolled kind and may give him its talent (`PlayerRecord.talent`, optional). `dress` sends talents to the ice through `TeamSetup.skaterTalents`, the same road the mascot's take.
- One concern per file: `rink.ts`, `skater.ts`, `puck.ts`, `shot.ts`, `aim.ts` (aim assist for the human's shots; pass assist is `assistedPassTarget` in `pass.ts`), `pass.ts`, `check.ts`, `goalie.ts`, `contact.ts` (bodies and loose-puck pickups), `control.ts` (which skater the human controls), `team.ts` (helpers).
- Every sim function takes the tuning object as an argument; only `src/sim/tuning.ts` reads `src/data/physics.json`. That is what lets the tuning panel change values mid-game.
- Units are metres and seconds. Y points down the screen.
- `src/game/RinkScene.ts` runs as many fixed steps as real time needs each frame, then draws. `src/game/input.ts` turns controller and keyboard into one `InputFrame`; button numbers and keys are in `src/data/controls.json`. `src/ui/GameSummary.tsx` is the end-of-game screen.
- Tuning panel: `src/ui/tuningStore.ts` and `src/ui/TuningPanel.tsx`. It lists every number in `physics.json` automatically. Edits are kept in the browser until Reset. Export JSON downloads a replacement `physics.json`. Log tuning changes in `docs/TUNING.md`.
- `npm run measure -- shape [--player script|passer|idle]` counts what nothing else does: how often a team-mate is open near the net while the stand-in carries in their end, what becomes of rebounds, and what happens in the last minute of a one-goal game. `npm run measure -- bosses [--player script|passer|outlet] [--boss id]` plays any stand-in against the bosses. The `outlet` stand-in (`createOutletPlayer`) is the passer with one more habit: pressed in its own half it passes to the man furthest up the ice.
- **Three stand-ins for a person** (`tests/harness/bot.ts`): the passer (`createPasserPlayer`: carries in like the script, but passes to a team-mate at the net and shoots first-touch), the script (`createNaivePlayer`: carries in and shoots for the corner, never passes or checks, never tires of it) and the newcomer (`createNovicePlayer`, numbers in `NOVICE`: slow to react, steers roughly, idles a fifth of the time, shoots from too far with a short wind-up). `standIn(who, t, seed)` picks one; `measureDefence` and `measureSeasons` take `who`. The newcomer is very sensitive to its numbers: read its results as a floor, not a forecast.
- **The five-complaints checks**: `tests/harness/checks.ts` (`measurePlay`, `checkRate`, `measureSeasons`) measures switching, team-mates, goalie fairness, check odds and whole-season win rates with the scripted player. The numbers and what they mean are in `docs/TUNING.md`; re-run after changing AI, checking, goalies or the season's difficulty. `WorldOptions.holdSwitch` (`Human.hold`, `Prefs.holdSwitch`) keeps control on your skater until you press switch.
- Balance harness: `tests/harness/harness.ts` (`runGame`, `runSeries`) and `tests/harness/bot.ts` (a scripted stand-in for a simple human). `scripts/balance.mjs` runs them from the command line through Vite. The targets and the latest numbers are in `docs/TUNING.md`; re-run the series after any change to ratings, AI or goalie values.
- Tests read the shipped tuning and assert relative to it. `tests/helpers.ts` has helpers to place players and hand out the puck.

## How two devices would fit together (step 0 only)

- `src/sim/online.ts` (pure, numbers in `src/data/online.json`): `OnlineHost` runs the game and sends a short word every few steps (the inputs it used, where everyone is, a few exact facts) or the whole game (`HostMessage`); `OnlineGuest` keeps `confirmed` (the host's game, followed step for step and patched with the host's figures) and `predicted` (that run ahead on his own controls: the picture). Both step only with `wireInput(...)`, the input as the wire carries it. Nothing here knows what carries the messages, and nothing in `src/game` or `src/ui` uses it yet.
- `tests/harness/online.ts` joins the two with a wire that delays and loses messages (`measureOnline`); `npm run measure -- online` prints the figures in `docs/TUNING.md`. Re-run it after changing `online.json` or the messages.
- A world must survive being sent as text (`throughText`; a test steps a copy beside the original): nothing that matters in a world may be `NaN`, `Infinity` or `undefined`.

## Notes for future sessions

- On the ice it is 3 skaters and a goalie a side; 6 skaters and 1 goalie are dressed (two lines of 3). Where a prompt in `docs/IMPLEMENTATION_PLAN.md` says 2 skaters, 4 skaters or lines of 2, `docs/GDD.md` and `docs/DECISIONS.md` win.
- The plain link opens the main menu: Career (the hub; "Start the season" begins a run), Exhibition (a one-off that does not count) and Practice.
- Difficulty (`f.difficulty`, set in Settings between seasons) shifts opponent AI level, and the easier ones have more strikes (`extraStrikes`: Rookie two, Semi-Pro one). Rookie alone also has later opponents play below their ratings (`regionRating`, `playoffRating` on a difficulty, read in `plainMatchup`) and wipes every strike on a boss win (`bossHeals`): its AI level was already at the floor, and without this the newcomer stand-in cleared region three 17% of the time. Its description says so, because every other setting changes thinking only. There are four: Rookie, Semi-Pro, Pro, All-Star. A difficulty may also set the steps of help, though none does today. Ordinary map games can be simulated (`simulateGame`); the run currency is called Pucks in everything the player reads (the field is still `season.currency`).
- Keyboard fallback: arrows or WASD skate, Space shoot (Z or J while winding up: fake), Z or J pass and faceoff draw, X or K check, C or L switch player, Q line change (LB), 1 and 2 powerups (LT and RB), G pull the goalie (View button), Shift sprint, Tab or Escape pause (Menu button; the tuning panel opens from the pause menu), I AI debug overlay (keyboard only).
- Balance (AI against AI, level 0.5) meets the Phase 3 targets. Human against AI is not balanced yet: a scripted player that only skates to the slot and shoots still wins about two games in three at the default difficulty of 0.75.
- In local development `window.__game` is the Phaser game. When the browser tab is hidden, animation frames stop; drive them by hand with `__game.loop.step(timeMs)`.
- The desktop app's "start preview" tool hung on this PC right after Node.js was installed. If it still does, start the server from a shell with `npm run dev` and open http://localhost:5173/hockey-roguelite/.

- `src/ui/PadReadout.tsx` shows live what the game reads from the controller and the on-screen buttons (pause menu, Controls; Settings, Controller test). Use it first when a button "does nothing" on a real device.

A binding is a button or an axis pushed one way.

A controller only appears after its first button press. `readGamepad` does not take the first device listed: `pickPad` stays with the controller in use and moves to another only when that one is being pressed and the current one is not (phones list fingerprint readers and remotes as controllers). `seenPads` lists them all; the read-out names the ones not in use.
